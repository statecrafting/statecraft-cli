# 028: Agent attribution and agent commit identities are refused

## 1. Purpose

Spec 001 refuses agent-session URLs and attribution trailers in repository
content, but its mechanical check does not cover every form current agents
write. It also reads commit messages without judging the author and committer
identities attached to those commits. A platform-valid signature proves who
signed a commit, not that the repository owner authored it.

This amendment closes both gaps. Project settings prevent Claude Code from
adding attribution. The authored-content checker refuses attribution that is
still presented to it and rejects known agent addresses in commit identity.

## 2. Territory

This spec establishes `.claude/settings.json`, adds that file to the index's
extra hashed inputs, and extends `scripts/check-authored-content.sh`. It edits no
rendered workflow, policy, or script under `scripts/statecraft/`. The existing
governance job already exports `BASE_SHA` while invoking the authored-content
checker, so no setup-profile change is required.

## 3. Behavior

### 3.1 Project settings write no attribution

`.claude/settings.json` MUST set `attribution.commit` and `attribution.pr` to
empty strings and `attribution.sessionUrl` to false. A Claude Code session in
this repository then writes no co-author trailer, pull-request footer, or
session link by default.

### 3.2 The checker refuses agent links and attribution

In every mode that reads text, the checker MUST refuse, case-insensitively:

- Claude chat or code links naming a conversation, session, or project;
- Codex session and cloud-task links;
- a co-author trailer whose address is at `anthropic.com` or `openai.com`, or
  is the GitHub no-reply address of the Claude, Copilot, Gemini Code Assist, or
  Codex connector account;
- a `Generated with` or `Generated by` footer naming Claude Code or Codex;
- the Claude Code projects-attribution marker; and
- a `Session-Id`, `Session-URL`, `Agent-Session-Id`, or `Agent-Session-URL`
  trailer with a non-space value of at least eight characters.

A co-author trailer with a person's address MUST pass regardless of its display
name. Product pages, documentation paths, and prose that merely mentions a
trailer MUST pass. The checker MUST NOT match its own source.

### 3.3 The checker refuses an agent commit identity

`--identity BASE HEAD` MUST judge the author and committer address of every
commit in `BASE..HEAD`. It MUST refuse each commit where either address is,
case-insensitively, `noreply@anthropic.com` or the Claude GitHub account's
no-reply address, with or without its numeric prefix. Display names MUST NOT be
judged.

With no argument, the checker MUST apply the same judgment to
`BASE_SHA..HEAD` when `BASE_SHA` names a commit. An unset or all-zero
`BASE_SHA` names no identity range. A value that names no commit is refused as
an unmet precondition. An explicit `--identity` endpoint that names no commit
is a usage error.

### 3.4 Offline evidence

`--self-test` MUST cover every refused form in section 3.2 and representative
passing near misses. It MUST also cover an agent author, an agent committer, a
human address whose display name is Claude, no-argument identity checking, an
all-zero and invalid `BASE_SHA`, and an empty identity range. Refused samples
MUST be assembled at run time so the checker does not match its own source.

## 4. Out of scope

- Editing rendered CI files or the setup profile.
- Rewriting existing branch history.
- Restricting human contributors to an allowlist.
- Policing ordinary pull-request comments, which do not enter Git history.

## 5. Resolved decisions

**Identity is judged through the existing `BASE_SHA` input.** The governance
job reads the checker at the trusted base and already exports the candidate's
base. The check therefore binds after this change lands without letting a
candidate judge itself.

**Addresses, not display names, decide identity.** A human may be named Claude,
and this repository accepts contributors not known in advance. A narrow denylist
blocks known agent identities without creating an owner allowlist.

## Verification

scripts/check-authored-content.sh
