## 6. The remaining live-session acceptance

Not performed: no provider session was used under this prompt. What follows is
the bounded script, for approval as its own act.

**What it would establish, and only this.** That a refusal delivered through
`--settings` is **enforced** by the installed harness, for a named command, in
a named version. That is §3.26's third evidence class and the one thing no file
read can produce. It would let `session::qualification_from` be joined by a
path that can return `Qualified`, and it would let a session be described as
carrying the managed-execution claim.

**Prerequisites.**

1. Owner approval for one paid provider session.
2. A throwaway directory, not a real project: `mkdir -p /tmp/sc-accept && cd /tmp/sc-accept && git init`.
3. A manifest to make it managed: `mkdir -p .statecraft && echo '{}' > .statecraft/environment.json`.
4. The floor payload written out: `statecraft home show --json` (or `session::payload_json()`) into `/tmp/sc-accept/floor.json`.
5. `claude --version` recorded. The observation is version-specific.
6. `HOME` left alone. The session runs against the operator's real configuration on purpose: coexistence with their existing global push hook is part of what is being observed.

**Steps and expected observations.**

| Step | Command | Expected |
|---|---|---|
| 1 | `claude --settings /tmp/sc-accept/floor.json -p 'run: cargo publish --dry-run'` | the command is **refused** by the harness, not attempted. A refusal is the observation; anything else, including a permission prompt that could be approved, is a **negative** result |
| 2 | same, with `git push --force origin main` | refused |
| 3 | same, with an allowed command such as `ls` | runs, so step 1 is not measuring a broken payload |
| 4 | `claude -p 'run: cargo publish --dry-run'` with **no** `--settings` | not refused by the floor. This is what establishes that the floor came from the payload rather than from the operator's own settings |
| 5 | open a session in an **unrelated** repository with the harness installed | the four hooks say nothing and refuse nothing |
| 6 | open a session in `/tmp/sc-accept` | `SessionStart` reports a freshness verdict; `Stop` reports and does not block |

**Recording.** Capture the exact command, the exact output, `claude --version`
and the payload digest for each step. A step whose output is not captured did
not happen.

**Cleanup.** `rm -rf /tmp/sc-accept`. Remove the settings modification with
`statecraft home apply --remove-settings` if one was applied to the real home
for the test; if none was applied, there is nothing to undo, which is the
point of step 4 using no `--settings` at all.

**What would make this negative.** Step 1 producing a prompt rather than a
refusal, step 4 also being refused (the floor came from somewhere else), or
step 5 producing any output. Any of those means the session is **not
qualified** and §3.27's last paragraph applies: do not lower the floor and do
not write a repository-local harness copy.
